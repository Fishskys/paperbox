# 测试行为边界

测试的保留标准是：失败能说明用户会遇到什么问题。用户包括 REST/MCP 调用方、CLI 操作者，
以及需要可靠导入、检索和管理论文的人。纯函数与服务层测试可以保留，只要其断言对应独立的业务规则，
例如论文去重、匹配冲突、证据页码、检索排序、权限拒绝、重试和回滚后的数据状态。

## 独立预期

- 预期来自接口契约、业务规则、手算结果或已确认的缺陷场景，不从被测实现的结果反推。
- 测试输入必须能区分正确实现与错误实现。例如验证相关度优先时，让高相关论文明确早于低相关论文，
  避免“按时间排序”的错误实现也通过。
- 元数据输入、输出相同本身不代表测试无效：通过实际 HTTP、MCP 或业务操作验证数据传递有价值；
  仅构造 Pydantic 对象后重复断言构造参数、且已有行为覆盖的用例不保留。

## 不约束内部写法

不测试 ORM 列名和关系名清单、索引名、内部对象身份、singleton、私有函数调用次数、
代码常量之间是否相等，或一个薄封装是否恰好转调指定函数。数据库约束通过重复写入、删除后重新导入、
主文件选择等行为验证；权限通过真实业务端点返回的拒绝响应验证。

外部协议需要的字段、第三方请求体、配置校验、独立数学公式和错误码是有效契约。
外部请求次数若关系到重复收费、重复写入、缓存复用或重试预算，可以断言；
普通内部函数调用次数不能代替最终结果检查。慢测试不因耗时而删除，也不因失败而删除。

## 隔离与执行

普通路由测试不进入生产应用 lifespan。确需验证启动行为时，替换 bootstrap、维度检查、
队列恢复和 housekeeping 等外部边界；健康探针使用本地 transport 替身。
SQLite、内存对象存储和可控的向量替身用于保持测试结果可重复。
凭证相关测试显式使用空值或固定假凭证，不读取本机真实 key 作为断言预期；公共下载链接须在两种配置下都保持相同路径且不携带凭证。

完整单元测试使用 `uv run python scripts/test_unit.py`，在导入应用前禁止 IPv4/IPv6 TCP 连接，并在 SQLAlchemy 调用驱动之前拒绝非 SQLite 数据库连接，覆盖 libpq 绕过 Python socket 的路径；保留异步运行所需的本机 Unix socket。鉴权中间件测试也须显式替换自己的会话工厂，不能只替换 HTTP 路由的数据库依赖。真实 PostgreSQL、OpenSearch、MinIO 与推理服务的验收放在
`scripts/`，不混入默认 `tests/` 套件。模型声明检查不能代替真实数据库迁移验收，
模拟请求体检查也不能证明真实检索引擎或推理模型可用。

## 自动合并检查

GitHub workflow `Verify` 对每个 PR 和 main 推送运行 `backend`、`frontend`、`contracts`、`migrations`，没有按目录跳过检查。`merge-gate` 只有在四项全部成功时通过；取消、跳过或失败均失败。仓库分支保护应要求 `merge-gate`，工作流文件本身不会修改远端分支保护设置。

前端检查包含 lint、类型、单元、生产构建和全部使用替身的 Playwright 流程；失败保留浏览器 trace。`npm run check:contracts` 从不执行 lifespan 的 OpenAPI 导出中读取结构，使用已安装的 TypeScript 编译器检查 WebUI 使用的 Paper、Job、队列、身份、重提取、维护任务及批量报告响应字段名称和非空值类型，以及维护请求形状。客户端可只声明实际消费的字段；此检查不代替 HTTP 状态码、空值行为与业务测试。

迁移检查使用独立 PostgreSQL 测试服务。`scripts/check_migrations.py` 只接受显式环境变量 `PAPERBOX_MIGRATION_TEST_DSN`，拒绝已包含应用表的数据库，在独立 schema 和版本表中执行 `base -> head -> base -> head`，核对模型表及列，最终清除 schema。不要将该变量设为部署数据库；真实业务验收脚本与默认单元测试分开执行。
