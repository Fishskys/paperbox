# 个人数据与同步边界

状态：已接受的设计约束；收藏、批注和跨设备同步尚未实现。

## 当前能力

API key 表达 read/write/admin 权限，可以由多人共享；`prefix` 是可更换、可吊销的凭证标识，不是用户 ID。公开读取没有个人身份。检索与阅读记录保存在当前浏览器，不能视为跨设备数据。

`paper_tags` / `papers_tags` 已保存论文的共享标签，`kind` 区分 IEEE、作者、动态术语与 `source_tag`；它们不代表某人的收藏或私有标签。现有标签来源及元数据导入行为保持共享语义。

## 设计决定

| 逻辑实体 | 数据与约束 |
|---|---|
| 数据所有者 | 独立且稳定的 owner ID；个人数据必须归属 owner，不能用 API key prefix 作为外键。单人部署也须显式绑定一个所有者，不能根据匿名访问猜测身份。 |
| 凭证绑定 | key 与 owner 的绑定独立于角色；轮换密钥不迁移或丢失收藏。共享 key 不能区分多个人，只有完成绑定后才可开放个人数据接口。 |
| 收藏 | `(owner, paper)` 唯一、含创建时间与版本；与共享标签分开存储。 |
| 私有标签 | 名称归属 owner；关联记录包含 owner 与 paper，不改变元数据中的来源标签。共享标签编辑继续属于论文管理。 |
| 批注 | owner、paper、文件版本 ID、PDF SHA256、页码、区域坐标或引用文本/偏移、内容及版本。换主 PDF 不静默移动批注；原件缺失时保留锚点并标记不可定位。 |
| 同步记录 | 服务端递增修订、设备游标、请求编号和删除墓碑。写入带期望版本，版本不符返回冲突；不能仅以设备时间覆盖服务端内容。 |

个人数据与修订保存在 PostgreSQL；附件才进入对象存储，OpenSearch 不是个人数据的唯一存储。服务端按 owner 校验读写范围，库级 read 权限不自动获得他人的私有数据，管理员能力也不等同于个人数据所有权。

论文软删除和判重归并需保留引用关系与墓碑；只有确认相同文件的归并才能自动保留批注定位。所有迁移必须有可回放的旧值、新值、操作者、时间及修订记录。现有浏览器历史不能在缺少所有者确认时自动上传。

## 本次实现范围

仅提供管理员对显式选择的至多 100 篇论文执行元数据重新提取或重建索引，须先预览并保留逐项报告。沿用系统级批量维护的 admin 边界，write 保留单篇管理，read 入口保持只读。不新增账号、私有收藏、批注或同步 API。

批量删除没有实现；其独立设计须明确 admin 权限、冻结预览范围、文件/图片/索引连带影响、确认方式与逐项清理结果，不能复用维护任务参数隐式触发删除。
