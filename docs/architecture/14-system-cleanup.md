# 系统清理

清理保留策略由 `CLEANUP_*` 环境变量加载，新增自动历史清理默认关闭。原有上传 GC 的开关和重试保护不受影响。普通缓存不包含元数据来源、字段历史及人工决定。

`cleanup_candidates` 保存每次扫描的固定候选及版本、保护原因和逐项结果；不能在应用时重新执行会扩大的查询。`cleanup_receipts` 独立于任务和论文保存轻量请求回执，报告裁剪或论文永久删除不能让旧请求重新执行。`managed_search_indices` 按物理索引 UUID 与集群 UUID 登记管理员认领的索引，不凭名字或版本后缀获得删除权。`cleanup_locks` 用于协调清理与应用管理的索引迁移。

永久删除仅接受至多 100 篇显式论文 ID；索引删除仅接受至多 20 个显式物理索引名，两者不与普通缓存混合执行。应用必须引用有效预览；预览期间的变化项跳过并报告，不扩大候选。

部署使用原生文件日志时可配置 `LOG_FILE`，`LOG_MAX_BYTES` 和 `LOG_BACKUP_COUNT` 限制轮转；容器 stdout 由容器日志驱动管理。当前活跃日志不能作为普通文件直接删除。
